> 课程期末项目 · 基于《要求.md》制定 · 2026-11-22

## 1. 项目概述

用 **Kotlin + Jetpack Compose** 从零开发一个"本地优先"的 Android RSS 阅读器。

**主链路（MVP）**：

> 添加订阅 → OkHttp 拉取 RSS → 解析 XML → 存入 Room → 列表展示 → 详情阅读 → 标记已读 → 手动/后台刷新

**加分项**：OPML 导入导出、WorkManager 周期同步。

**答辩演示场景**（要求文档第 7 节）：以"竞赛信息订阅"讲故事——
1. 高校竞赛通知 RSS（RSSHub 生成），展示"新通知以文章形式出现"；
2. 竞赛报名状态页的 Changedetection RSS，展示"状态变更以短通知形式出现"。

> 核心叙事：RSS 阅读器不只是读文章，它把"有列表结构的信息"和"只有状态变化的信息"统一成订阅流。

| 协作模式 | **我实现 + 里程碑讲解**（用户零 Android 经验，有 Java/OOP 基础），代码配中文注释，最终交付答辩讲解手册 | 用户确认 |
| 工期 | **不到三周**，MVP 优先级压实，时间不够先保 WorkManager 后砍 OPML | 用户确认 |

**已核实的 RSS-Parser 关键 API**（决定网络层架构）：

- `parser.parse(rawXml: String): RssChannel` —— 支持**传 XML 字符串解析**；
- `parser.getRssChannel(url)` —— 传 URL（内部自己拉取）；
- 网络层用**我们自己的 OkHttp** 拉取，再喂给 `parse()` 纯解析——分层符合要求文档"解析器只输出内存对象，入库/去重归 Repository"；
- 异常体系：`HttpException`（HTTP 状态错）、`RssParsingException`（XML 解析失败）——正好映射到我们的错误分类；
- `RssItem.pubDate` 返回**原始字符串** → 需自写多格式 `DateParser`（RFC-822 / ISO-8601）。

## 4. 参考项目研读结论（要求文档第 5 节指定）

> 策略：三个项目均为 GPL/AGPL 协议，**只借鉴设计模式，所有代码原创重写**。答辩时"参考了哪些开源项目的设计"本身就是加分回答。

### 4.1 Feeder（架构首选参考）

| 借鉴点 | 出处文件 |
|---|---|
| **去重靠 schema 不靠代码**：`(guid, feed_id)` 唯一索引 + `@Insert(OnConflictStrategy.IGNORE)` → 同步天然幂等 | `db/room/FeedItem.kt`、`FeedItemDao.kt` |
| UI 完全观察 Room `Flow`，同步只管写库，UI 自动更新 | `archmodel/FeedStore.kt` |
| 同步状态存 Feed 行（`lastSync`、`currentlySyncing`），UI 由 Flow 查询驱动刷新指示 | `archmodel/`、`model/RssLocalSync.kt` |
| **WorkManager 模式（取其 2.6.33 版实现，比 master 上的 JobScheduler 简单）**：周期任务 = unique work 名 + `ExistingPeriodicWorkPolicy.UPDATE` + `NetworkType.CONNECTED` 约束；"立即同步" = 同一 Worker 换一次性 unique work | `model/workmanager/FeedSyncer.kt`、`archmodel/SettingsStore.kt`(2.6.33) |
| 逐源密封类错误结果（`FetchError`/`HttpError`/…），**一个源失败不中断整个循环** | `model/RssLocalSync.kt` |
| feed → items 外键 `onDelete = CASCADE`（删订阅自动清文章） | `db/room/FeedItem.kt` |
| **永不用 feed 自报的 link 覆盖用户输入的 URL**（自报链接经常是错的） | `model/FeedParser.kt` |

### 4.2 Capyreader（轻量校准）

| 借鉴点 | 出处文件 |
|---|---|
| 文章 ID = `guid` 优先、`link` 兜底、**两者皆无则丢弃**（不发明哈希） | `accounts/local/ParsedItem.kt` |
| **条件请求**：缓存 ETag / Last-Modified，发 `If-None-Match`/`If-Modified-Since`，304 直接跳过解析 | `LocalAccountDelegate.kt` |
| 并发刷新信号量限流（≈4），避免同时打爆所有源 | 同上 |
| Worker 只做 20 行薄壳，委托给注入的刷新器 | `refresher/` |
| 其"文章表 DO UPDATE + 状态表 DO NOTHING"双表方案 → 作为答辩"进阶对比"素材写进讲解手册（本项目用 Feeder 的更简单单表方案） | `db/` migrations |

### 4.3 ReadYou（UI 参考）

| 借鉴点 | 出处文件 |
|---|---|
| 底部 **FilterBar**：`Surface + Row(selectableGroup) + NavigationBarItem`，未读/全部两档，`FiberManualRecord` 实心圆点图标本身即未读标记 | `ui/component/FilterBar.kt` |
| 文章列表项：feed 名+日期顶行、标题+摘要底行、Coil 缩略图；**已读项 `alpha(0.5f)`**——一行代码实现未读视觉 | `ui/page/home/flow/ArticleItem.kt` |
| 详情页：WebView 渲染正文 + 元数据头 + `uriHandler.openUri(link)` 打开原文 | `ui/page/home/reading/` |
| 下拉刷新：M3 `PullToRefreshBox`（ReadYou 自己也用这个，不用它的自研 PullToLoad） | `ui/page/home/feeds/FeedsPage.kt` |
| 主题：`dynamicLightColorScheme()`（Material You 动态取色，Android 12+）+ 静态 fallback，10 行拿到高级感 | `ui/theme/Theme.kt` |
| OPML：导出 `CreateDocument`、导入 `OpenDocument`（SAF 启动器形态） | `ui/page/settings/` |

## 6. 数据库设计

```sql
feeds 表
  id            主键
  url           用户输入的订阅地址（永不改写 —— Feeder 原则）
  title         显示名（可重命名）
  lastSyncAt    上次同步时间（UI 显示 + 驱动刷新指示）
  lastSyncError 可空 —— 逐源错误显示"上次同步失败"，不静默
  etag          可空 —— 条件请求
  lastModified  可空 —— 条件请求

articles 表
  id            主键 autoGenerate
  feedId        外键 → feeds.id，onDelete = CASCADE
  articleKey    = guid ?: link（guid 缺失时用 link 兜底）
                ← 唯一索引 (feedId, articleKey)
  title / link / description / content / imageUrl
  pubDate       解析后的 epoch 毫秒，可空（解析失败置空，排序垫底）
  fetchedAt     入库时间
  isRead        已读状态
```

**核心机制**：刷新插入用 `@Insert(onConflict = OnConflictStrategy.IGNORE)` —— 已存在的文章整行跳过 → **已读状态天然不丢失**，同步幂等（Feeder 验证过的最简方案）。

**列表排序**：`ORDER BY isRead ASC, pubDate DESC`（未读优先、时间倒序）。

## 8. 关键实现要点

1. **添加订阅先验证**：真实拉取 + 解析成功才入库；失败则不入库、Snackbar 报具体原因（`SyncError` 分类：网络失败 / HTTP 状态码 / XML 解析失败）。
2. **刷新流程**（Repository 内，信号量限流 4 并发逐源）：条件请求 → 304 则跳过 → `parser.parse(xml)` → 逐条映射（`guid ?: link` 兜底、`DateParser` 多格式、无日期置 null）→ IGNORE 批量入库 → finally 里 `NonCancellable` 更新 feed 行的 `lastSyncAt`/`lastSyncError`。**一个源失败记录后继续下一个**。
3. **WorkManager**：`enqueueUniquePeriodicWork("rss_periodic", UPDATE, 间隔 + CONNECTED 约束)`；间隔存 DataStore，设置页可改（默认 4 小时）；设置页"立即同步"按钮 = 同一 Worker 一次性 unique work（答辩现场演示用）。
4. **UI**：底部 FilterBar（未读/全部）→ 文章列表（已读 `alpha 0.5`、Coil 缩略图、点击进详情自动标已读）→ 详情页 WebView 渲染正文 + "浏览器打开原文"；订阅页长按 → ModalBottomSheet（重命名/删除）；`PullToRefreshBox` 下拉刷新；`dynamicColorScheme` + 静态 fallback；空状态、加载失败、无网络提示齐全。
5. **OPML**：SAF `OpenDocument` 导入（批量插库 + 触发全量刷新）、`CreateDocument` 导出（标准 outline）。

**开发期测试源**（真实、格式有代表性）：
- 少数派 `https://sspai.com/feed`（RSS 2.0）
- V2EX `https://www.v2ex.com/index.xml`（**Atom**，验证双格式兼容）
- 36氪 `https://36kr.com/feed`
